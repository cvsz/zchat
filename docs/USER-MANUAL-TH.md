# คู่มือผู้ใช้ Camfrog

English version: `USER-MANUAL-EN.md`.

แปดแอป หนึ่งคู่มือ

แอป: `room-control`, `chat-im-private`, `status-random`, `status-marquee`, `status-changer`, `im-autoreply`, `music-dj`, `web-status` ทุกแอปใช้ได้เฉพาะ Windows และต้องเปิด Camfrog ไว้ ยกเว้น `web-status` ที่ทำงานผ่านเว็บไซต์

**อัปเดต** ทุกแอปตรวจ GitHub release ตอนเปิด (ขึ้น banner เฉพาะเมื่อมีเวอร์ชันใหม่) และมีปุ่ม **Check for updates** ส่วน CLI ใช้คำสั่ง `<app> update` การอัปเดตดาวน์โหลดเฉพาะไฟล์ของแอปนั้น ตรวจกับ `SHA256SUMS.txt` ของ release แล้วติดตั้งตอนปิดแอป (`<app>.new` กับ `camfrog-update.cmd` เป็นตัวสลับไฟล์) ไม่ต้องมีบัญชีหรือโทเคน และไม่ส่งข้อมูลอะไรขึ้น GitHub เลย เผยแพร่ release ด้วย `python tools/release.py`

## 1. ติดตั้ง

1. ติดตั้ง CPython 3.12 รุ่นปกติ แบบ 64-bit
2. รัน `doctor.bat` ก่อน เพื่อตรวจ Python และทดสอบการโหลด `pywin32`
3. ดับเบิลคลิก `build.bat` เพื่อ build แอป Camfrog ทั้งแปด หรือรัน `full-build.ps1` ใน PowerShell เพื่อ build พร้อมแอป LINE ไฟล์ exe จะอยู่ใน `dist\<app>\`
4. ถ้า build ขึ้น `pywin32 ... no matching distribution` แปลว่า Python รุ่นนั้นไม่มี wheel ให้ติดตั้ง Python 3.13 แบบ 64-bit ลบ `.venv` แล้วรันใหม่

## 2. เริ่มใช้ครั้งแรก

1. เปิด Camfrog แล้วเข้าห้อง (อย่าย่อลง tray)
2. เปิด Camfrog ก่อน แล้วจึงเปิดแอป standalone ที่ต้องการ แอป Camfrog ทุกตัวจะลองค้นหา control และบันทึก selector ที่ผ่าน validation ให้อัตโนมัติ ส่วน Web Status ใช้ control บนเว็บไซต์ ใช้ **Setup → Auto-detect** หรือ **Discover controls** เพื่อลองใหม่ และตรวจ selector ก่อนเปิด live actions
3. เปิด `dry_run` ไว้ก่อนเสมอขณะทดสอบ โหมดนี้แค่บันทึกว่าจะส่งอะไร ไม่ส่งจริง
4. คงโหมดทดลองไว้ระหว่างตรวจสอบ โหมด strict จะคืน `BACKGROUND_UNSUPPORTED` โหมดเดิม `best_effort_background` ถูกปิด เพราะทดสอบบน Windows พบว่า Camfrog ดึง focus ได้และรบกวนคีย์บอร์ด โหมด interactive จะรอให้ผู้ใช้หยุดใช้งาน desktop ก่อนใช้อินพุตจริง ดู `docs/STATUS-SUBMIT-MODES.md` ส่วน `web-status.exe` ใช้เว็บไซต์แยกต่างหาก

## 3. ควบคุมห้อง

- ตั้งนิคของตัวเอง (`My nickname`) จำเป็นสำหรับโหมดจริง
- **Window title regex** ใช้เลือกว่าจะควบคุมหน้าต่าง Camfrog ใด
- กฎตอบอัตโนมัติ: รูปแบบ regex, ข้อความตอบ, คูลดาวน์รายคน, ตอบเฉพาะเมื่อถูกเรียกชื่อ, ภาษา (`th`/`en`) ทดสอบด้วย **Test rule** ก่อนเปิดจริง
- **Save & Start** เริ่มบอทเบื้องหลัง **Stop** หยุด ปิดหน้าต่างไม่ทำให้บอทหยุด
- กันสแปม: ไม่ตอบข้อความที่มีลิงก์ (ค่าเริ่มต้น `ignore_links`) และข้ามตาม `skip_patterns`

## 4. ตอบแชทส่วนตัว

- แอปแยก config แยกกฎ การตอบในห้องไม่ยุ่งกับแชทส่วนตัว
- **ต้องระบุรายชื่อเพื่อน** (`only_nicknames`) ตอบเฉพาะคนที่อยู่ในรายชื่อ
- เพดานเข้มกว่าปกติ (ค่าเริ่มต้น: ตอบเพื่อนคนละ 1 ครั้งต่อชั่วโมง วันละ 3 ครั้ง รวมชั่วโมงละ 10 ครั้ง) ทุกคำตอบขึ้นต้นด้วย `[auto] ` และจะไม่ตอบบรรทัดที่มีคำนำหน้านี้
- หน้าต่างที่เปิดอยู่ก่อนบอทเริ่มจะไม่ถูกตอบ
- หลังตอบโหมดจริง IM Auto-reply จะหา echo ของข้อความขาออกในประวัติแชตฝั่งเครื่อง แล้วเลื่อนไปยังบรรทัดนั้น นี่เป็นหลักฐานจาก UI ในเครื่องเท่านั้น Camfrog ไม่มีการตอบรับยืนยันว่าผู้รับเห็นข้อความ ถ้าส่งไม่สำเร็จก่อนกดส่ง ระบบจะเก็บข้อความไว้ลองรอบถัดไป แต่ถ้าผลกำกวมจะไม่ส่งซ้ำเพื่อป้องกันข้อความซ้ำ ตั้ง `safety.restore_previous_window` เป็น `false` หากต้องการให้หน้าต่างแชต Camfrog ค้างอยู่ด้านหน้า
- แท็บ **Activity Log** แสดง log ของแอปตามไฟล์ที่ตั้งไว้ บันทึกการเปิด/ปิดแอป การบันทึก/โหลด config ผล Start/Stop และ helper วงจรชีวิต worker การกรอง IM กฎที่ไม่ตรง ตัวอย่างตอบกลับ การตอบ และ error พร้อมรายละเอียดที่มีอยู่ หน้าจอจะอัปเดตขณะเปิด GUI ตัวเลือก **Log chat text** ใน Advanced กำหนดว่าจะบันทึกเนื้อหาข้อความด้วยหรือไม่ ให้ปิดเพื่อไม่เก็บข้อความแชตใน log แต่ละแอปใช้ไฟล์ log และ worker ของตัวเอง
- โฟลเดอร์ข้อมูลของแอปนี้รัน worker ได้ครั้งละหนึ่งตัว Activity Log จะแสดงเมื่อไม่มีกฎตอบที่ตรงหรือมีการกรองข้อความ

## 5. จัดการหน้าต่างแชทส่วนตัว

- แสดงรายชื่อหน้าต่างแชทส่วนตัวที่เปิดอยู่ **Refresh** โหลดใหม่ ดับเบิลคลิกหรือ **Activate selected** เพื่อโฟกัส ไม่มีการอ่านหรือส่งข้อความ
- ตัวกรองชื่อหน้าต่าง (regex) กับจำนวนสูงสุดช่วยจำกัดรายชื่อ **Save filters** บันทึกลง config ของแอปนี้
- **Discover controls** ลองค้นหาใหม่และบันทึกรายการ control ลง `controls.txt` สำหรับตรวจวิเคราะห์

## 6. Status Changer: Random, Marquee และ Activity Log

- `status-changer.exe` แยก Random และ Marquee เป็นคนละแท็บและแยก pool สิบช่อง หากพบฐานข้อมูล pool จากโฟลเดอร์เดิมจะนำมาใช้ exe `status-random.exe` และ `status-marquee.exe` รุ่นเดิมยังอยู่เพื่อรองรับการใช้งานเดิม
- **Random:** สุ่มข้อความจากสิบช่อง **Switch every** ตั้งช่วงวินาทีขั้นต่ำ 10 วินาที
- **Marquee:** **Step** ตั้งวินาทีต่อเฟรม และเป็นช่วงหน่วงก่อนเปลี่ยนช่องเมื่อปิด Scroll (ขั้นต่ำ 0.3 วินาที; GUI ปรับทีละ 0.1 วินาที ค่าเริ่มต้น 0.5 วินาที) ทุกเฟรมคือการส่งสถานะจริง **Stride** ตั้งจำนวนกลุ่มตัวอักษรต่อเฟรม และ **Scroll** เปิดหรือปิดการเลื่อน Marquee จะใช้ช่องที่มีข้อความเรียงตามลำดับ และ History จะไม่สลับลำดับช่อง เมื่อเปิด Scroll แต่ละช่องจะเลื่อนจนจบก่อนเริ่มช่องถัดไป **Loop slots** จะเริ่มช่อง 1 ใหม่หลังช่องสุดท้าย หากปิดไว้จะหยุดหลังช่องสุดท้าย ระบบไม่แยกสระหรือวรรณยุกต์ไทยออกจากพยัญชนะ ค่า **Switch every** ใช้กับ Random เท่านั้น
- **Start** เริ่มโหมดที่เลือก โดยส่งสถานะครั้งแรกหลัง 10 วินาที เปิด worker ได้ครั้งละโหมดเดียว หน้าต่างแสดงว่าโหมดใดกำลังทำงาน **Stop** หยุด worker
- **Activity Log** รวมเหตุการณ์จาก GUI กับ log ของ worker ทั้งสองโหมด รายการ GUI ไม่เก็บข้อความสถานะ ส่วน log ของ worker จะแยกการส่งคำสั่งในเครื่องออกจากการยืนยันผลที่ Camfrog กด **Open log folder** เพื่อเปิดโฟลเดอร์ไฟล์ log

## 7. ประวัติ ตารางเวลา ภาษา

- ข้อความยาวเลื่อนผ่านหน้าต่างกว้าง `width` ตัวอักษร: **Step** (วินาทีต่อเฟรม ขั้นต่ำ 0.3 ปรับทีละ 0.1) **Stride** (กลุ่มอักษรต่อเฟรม) **Loop** (วนไม่หยุด) ถ้าปิด **Scroll** (ค่าเริ่มต้น) จะส่งทีละ 1 บรรทัดเต็มต่อรอบ วน 1..N
- Random และการ retry อัตโนมัติยังเว้นอย่างน้อย 10 วินาที ส่วนเฟรม Marquee ใช้ Step ที่ตั้งไว้ (ขั้นต่ำ 0.3 วินาที) และรอ 10 วินาทีก่อนเปลี่ยนสถานะครั้งแรกหลังเริ่มทำงาน
- ทุกเฟรมคือการเปลี่ยน status จริง ตั้งให้ช้าและน้อยเฟรม เริ่มด้วย dry-run เสมอ
- ใช้ `status-changer.exe` หากต้องการหน้ารวมโหมดสุ่มและ Marquee พร้อม Activity Log โดยเก็บ settings, pool และ log แยกใน `status-data\` และทำงานได้ครั้งละหนึ่งโหมด
- ปลอดภัยภาษาไทย: ไม่ตัดสระ/วรรณยุกต์ ไม่สร้างเฟรมว่าง

## 8. ประวัติ ตารางเวลา ภาษา

- ทุก status ที่ตั้งถูกเก็บลงประวัติ ถ้าเปิด `use_as_source` จะสลับเลือกจากประวัตินั้น (`rotate`/`random`/`most_used`)
- ตั้ง pool ต่างกันตามช่วงเวลาของวัน (`status.schedules`) ระบุ `start`/`end` เป็น `HH:MM`
- `status.language_cycle: ["th","en"]` สลับไทย/อังกฤษทุกครั้งที่เปลี่ยน status รายการสถานะเป็นคู่ `{th, en}` ได้
- `"language": "auto"` ตามภาษาหน้าจอ Windows อัตโนมัติ

## 8. ดีเจเพลง

- บอทห้องที่เล่นเพลงได้พร้อมรับคำขอจากแชท ต้องเปิด Camfrog และเปิด `autoreply` (ดีเจใช้ระบบอ่านแชทนี้) แล้วตั้ง `dj.enabled`
- คำสั่งในแชท ค่าเริ่มต้นนำหน้าด้วย `!`: `!request <เพลง>` (หรือ `!req`, `!song`), `!randommusic`, `!queue`, `!current` (หรือ `!np`), `!skip`, `!help` `!randommusic` ส่งลิงก์ค้นหาเพลง YouTube แบบสุ่มและเก็บไว้ใน `youtube_random_music.json` (สูงสุด 200 รายการ) `!current` แสดงผู้ขอ เวลาเล่น/ความยาวเมื่ออ่านได้ และเพลงถัดไป ในแท็บ Music มี Windows TTS ให้อ่านข้อความหรือสรุปเพลงปัจจุบัน หากต้องการให้ห้องได้ยิน ให้ต่อเอาต์พุตเสียง Windows เข้าไมโครโฟน Camfrog ผ่าน virtual cable หรือ Stereo Mix หน้าต่างคิวในแอปแสดงสถานะเดียวกับไฟล์ โดยมีปุ่มเจ้าของบอทคือ **ข้ามเพลงปัจจุบัน** / **ล้างคิว**
- คำขอแรกเล่นทันที เพลงถัดไปเข้าคิว (จำกัดต่อคนตาม `max_per_user` เพลงซ้ำหรือเพลงที่กำลังเล่นจะถูกปฏิเสธ) คำสั่ง `!skip` ใช้ได้กับผู้ขอหรือเจ้าของบอท
- โฟลเดอร์เพลง: กด **Browse** เพื่อเลือกโฟลเดอร์ แล้ว `!request` จะจับคู่ชื่อไฟล์เสียงที่รองรับ (ตรงบางส่วนของชื่อและไม่สนตัวพิมพ์เล็กใหญ่) แอปค้นหานามสกุลเสียงทั่วไป เช่น WAV, MP3, WMA, AAC/M4A, AIFF/AU, FLAC, OGG/Opus และ MIDI
- **Audio backend** `chat` (ค่าเริ่มต้น) จะประกาศในแชทอย่างเดียว `local` เล่นไฟล์ที่ Windows MCI เปิดได้และเริ่มเพลงถัดไปเมื่อเพลงจบ ส่วน `youtube` รับ URL หรือ ID วิดีโอ YouTube ผ่าน `!request` เปิด player มาตรฐานที่มองเห็นได้ใน Edge/Chrome แยกหน้าต่าง ประกาศหลัง player แจ้งว่าเริ่มเล่น และข้ามต่อเมื่อ YouTube แจ้งว่าวิดีโอจบ หาก autoplay ถูกปิด ให้กด **Play** ในหน้าต่าง player เพื่อให้ห้องได้ยินเสียงจาก player หรือไฟล์ในเครื่อง ต้องส่งเสียงของเครื่องนี้เข้า input ของ Camfrog ด้วย virtual cable หรือ "Stereo Mix" การทำงานขึ้นกับ Windows MCI เบราว์เซอร์ อุปกรณ์เสียง และ codec ที่ติดตั้ง
- เริ่มแบบ dry-run ก่อน: บอทจะแค่บันทึกว่าจะประกาศอะไร คำขอเพลงยังเข้าคิว แต่ไม่พิมพ์อะไรเข้าห้อง
- ในหน้า **Bot Manager → Music DJ** เลือก `music-dj.exe` (ถ้าใช้โครงสร้างโฟลเดอร์จาก zip ระบบจะลองหาให้อัตโนมัติ) หน้านี้เปิดหน้าต่างตั้งค่า Music DJ เริ่ม/หยุด worker อ่านคิว ข้ามหรือล้างคิว และส่งข้อความไม่เกิน 240 ตัวอักษรให้ Windows TTS อ่านเสียงได้ หากต้องการให้ห้องได้ยิน ให้ต่อเอาต์พุตเสียง Windows เข้าไมโครโฟน Camfrog worker ของ Music DJ ยังคงเป็นเจ้าของคำสั่งแชทและคิวเพียงตัวเดียว หากติดตั้งแยกกัน ให้กด **Browse** แล้วเลือกไฟล์โปรแกรม
- **YouTube assisted search** เปิดหน้าค้นหา Edge หรือ Chrome ที่มองเห็นได้และใช้โปรไฟล์แยก เลือกผลค้นหาแล้วคัดลอก URL มาใส่ใน `!request` player ของคิวใช้ตัวควบคุมมาตรฐานที่มองเห็นได้และรับ event เล่น/จบเพลง โปรไฟล์แยกเก็บที่ `%LOCALAPPDATA%\Camfrog\MusicDJ\YouTubeProfile` และไม่ใช้โปรไฟล์ล็อกอิน Camfrog ดูขอบเขตและการตรวจรับที่ [`zBOT-Youtube-MUSIC-DJ.md`](zBOT-Youtube-MUSIC-DJ.md)

## 10. สถานะผ่านเว็บและ Bot Manager

สถานะ: รู้ขั้นตอน login แล้ว และดึง endpoint อัปเดตสถานะได้จากหน้า home.php ที่ล็อกอินอยู่ (POST `{status, csrf}` ไป `/ajax/update_status.php`) แต่ยังกั้นไว้ CLI ที่ส่งจริงต้องใส่ `--confirm-update`; ปุ่ม Start ใน GUI จะแสดงคำถามยืนยันก่อนส่ง

- ไม่ใส่ argument เปิด GUI ใส่ argument ใช้ CLI (`web-status.exe --login Seaza --status "..."`) ค่าเริ่มต้นคือ dry-run ไม่มีการต่อเน็ต
- หน้าต่างปรับขนาดได้ เริ่มที่ 400×300 และย่อได้ถึง 300×220 ตอนเริ่มจะแสดงภาพ Idol พร้อมโลโก้ Zttato และข้อความ **Loading pages...** จากนั้นนับถอยหลัง 5 วินาทีแล้วปิดหน้า splash เองเพื่อเข้าสู่หน้า Setup กดโลโก้ **Z** เพื่อเต็มจอ ปุ่ม **800x600** คืนขนาดหน้าต่างตามนั้น ปุ่ม **Tray** ซ่อนหน้าต่างไว้ใน system tray; คลิกไอคอนเพื่อเปิดกลับ หรือคลิกขวาเพื่อออกจากแอป
- ในแท็บ Setup มีช่องสถานะแบบบรรทัดเดียว 10 ช่อง ปุ่ม **Save to webtext.db** จะบันทึกแยกตามหมายเลขลง `webtext.db` ข้างแอป และปุ่ม **Start** จะบันทึกค่าปัจจุบันก่อนวนเฉพาะบรรทัดที่ไม่ว่าง
- ในแท็บ Setup กรอกสถานะได้สูงสุด 10 บรรทัดในช่องหมายเลขแยกกัน ปุ่ม **Save to webtext.db** บันทึกแต่ละช่องไว้ข้างแอป และ **Start** จะบันทึกค่าปัจจุบันก่อนวนเปลี่ยนเฉพาะช่องที่ไม่ว่างทุก 60 วินาทีเป็นค่าเริ่มต้น และวนต่อจนกด **Stop**
- ในแท็บ **Account & Session** กด **Open login page** แล้วลงชื่อเข้าใช้ในเบราว์เซอร์ตามปกติ จากนั้นคัดลอก `PHPSESSID=...` จาก request ของ `profiles.camfrog.com/home.php` ใน DevTools แล้ววางในช่อง session กด **Login** เพื่อตรวจสอบ cookie ปัจจุบัน หากยืนยันว่าลงชื่อเข้าใช้แล้ว ระบบจะพร้อมทำงาน สำหรับ development ในเครื่อง สามารถตั้ง `WEBAUTH_USER=PHPSESSID=REPLACE_ME` ใน `.env` ที่ถูก ignore เพื่อเติมค่าในช่องแบบซ่อน โดยแอปจะไม่ verify หรือ arm session ให้อัตโนมัติ และจะไม่ส่ง cookie ไป ZChat Server
- เมื่อเลือก **Send live**, ปุ่ม **Start** จะตรวจ cookie ปัจจุบันหากยังไม่ได้กด Login เพื่อยืนยัน session จากนั้นถามยืนยันและเริ่มวนสถานะ ปุ่ม **Stop** หยุดการวนและยกเลิก session ที่ยืนยันไว้ ดังนั้น Start ครั้งถัดไปจะตรวจสอบใหม่ ค่าเริ่มต้นยังเป็น dry-run
- วงรอบ live ของ GUI จะเว้นการส่ง Random อย่างน้อย 10 วินาที เฟรม Marquee ใช้ Step ที่ตั้งไว้ (ขั้นต่ำ 0.3 วินาที) และรอ 10 วินาทีก่อนเปลี่ยนสถานะครั้งแรกหลังเริ่มทำงาน การ retry หลัง HTTP 429 จะรออย่างน้อย 10 วินาที แอป Web Status ที่เปิดแยกกันและการเปลี่ยนสถานะบน Camfrog โดยตรงไม่ได้ประสาน cooldown ร่วมกัน ส่วนจังหวะ preview แบบ dry-run ไม่เปลี่ยนแปลง
- ก่อน POST จริงแต่ละครั้ง Web Status ตรวจว่า nickname ในโปรไฟล์ที่ล็อกอินตรงกับชื่อที่เลือก และหน้าโปรไฟล์มี provider user ID หากชื่อไม่ตรงหรือไม่มี identity จะไม่ส่ง POST ขณะนี้ ID ยังไม่ได้ผูกกับทะเบียนบัญชี ZChat
- HTTP response ที่สำเร็จและมีข้อความตอบกลับหมายถึง Camfrog รับทราบคำขอเท่านั้น Web Status ยังไม่ได้อ่านโปรไฟล์กลับเพื่อตรวจว่าค่าเปลี่ยนจริงหรือไม่ หาก timeout, server error หรือ response ที่แปลผลไม่ได้ ให้ถือว่าไม่ทราบผลและตรวจโปรไฟล์ก่อนส่งซ้ำ
- แท็บ **Bot Manager** รับค่า `cloudbot=...` เพื่อตรวจสอบกับ `www.camfrog.com` แล้วโหลดหน้า **Room**, **Profile** และ **Plugins** สำหรับ development ในเครื่อง สามารถตั้ง `WEBAUTH_BOT_USER=cloudbot=REPLACE_ME` ใน `.env` ที่ถูก ignore เพื่อเติมค่าในช่องแบบซ่อน จากนั้นกด **Connect** เพื่อ verify cookie แอปส่ง cookie ไป Camfrog เท่านั้น ปุ่ม **Disconnect** ล้าง session ในแอป ส่วน **Log out** ออกจาก session บนเว็บ
- หน้า **Room** แก้ชื่อห้อง รหัสผ่านห้อง ภาษา และสถานะพักบอท หน้า **Profile** แก้รหัสผ่านและอีเมล ปุ่ม **Stop bot** ส่งคำสั่งหยุดบอทหลังยืนยัน
- หน้า **Plugins** แสดงปลั๊กอินที่ Camfrog รายงานว่าติดตั้งไว้ (แค็ตตาล็อกมาตรฐานใช้ ID 1–9 และ 11–16) พร้อมสวิตช์เปิด/ปิด เปลี่ยนสวิตช์แล้วกด **Apply changes** เพื่อส่งหลังยืนยัน จากนั้นแอปโหลดรายการกลับมาให้ตรวจสถานะที่ Camfrog ตอบ เลือกการ์ดปลั๊กอินเพื่อโหลดฟอร์มตั้งค่าปัจจุบัน ฟอร์มแปลงช่องข้อความ พื้นที่ข้อความ checkbox กลุ่ม radio ตัวเลือกเดี่ยว/หลายค่า และช่องอัปโหลดไฟล์ที่ Camfrog ส่งมาเป็นตัวควบคุมให้แก้ไข การบันทึกต้องยืนยันก่อนส่ง แล้วโหลดฟอร์มกลับมาให้ตรวจค่าที่ Camfrog ตอบ ชื่อปลั๊กอิน ป้ายกำกับ และตัวเลือกที่รู้จักจะแสดงตามภาษา TH/EN โดยค่าที่ส่งยังคงใช้ค่าเดิมจาก Camfrog และข้อความที่พิมพ์เองคงตามที่กรอก ฟอร์มรูปแบบข้อความรองรับแบบอักษร ขนาด สี ตัวหนา ตัวเอียง ขีดเส้นใต้ และขีดทับ

## 11. โปรแกรมเปลี่ยนชื่อ สีชื่อ และไอคอนแบบ Standalone

มีโปรแกรมแยกการทำงาน 3 ตัวสำหรับปรับแต่งชื่อและไอคอนในห้องแชท:

### ก. ระบบสลับสีชื่อเล่น (`name-color-changer.exe`)
- สลับสี Flair ของชื่อเล่น (Color A <-> Color B) ผ่าน API `profiles.camfrog.com/ajax/post_flair.php`
- ค่าเริ่มต้นเป็นโหมดทดลอง (Dry-Run); การรันส่งจริงต้องติ๊กยืนยัน (Confirm Live)
- ป้องกัน Rate Limit: เคารพ HTTP 429 และ header `Retry-After` โดยจะหยุดทำงานทันทีเมื่อพบสัญญาณเตือน
- คืนค่าสีเดิม: มีระบบพยายามคืนค่าสีเดิมเมื่อทำงานครบรอบตามกำหนดหรือหยุดการทำงานตามปกติ (หมายเหตุ: การปิดหน้าต่างทันทีหรือ kill process อาจข้ามขั้นตอนนี้)

### ข. ระบบสลับไอคอนหน้าชื่อในห้อง (`icon-changer.exe`)
- สลับไอคอนหน้าชื่อใน Room User List (Icon A <-> Icon B) ผ่าน `profiles.camfrog.com`
- ตรวจสอบรายการไอคอนที่บัญชีมีสิทธิ์ใช้อัตโนมัติจากหน้าการตั้งค่า
- ป้องกันข้อผิดพลาดแบบ fail-closed และพยายามคืนค่าไอคอนเดิมเมื่อทำงานเสร็จสิ้นหรือหยุดทำงานตามปกติ

### ค. ระบบสลับชื่อเล่นและรองรับภาษาไทย (`name-changer.exe`)
- ตัวต้นแบบโปรแกรมสลับชื่อและจัดการชุดรายชื่อในเครื่อง (Local Prototype) สำหรับจัดการสถานะชื่อเล่นและรายการชื่อในหน่วยความจำ
- หมายเหตุ: ตัวต้นแบบนี้จัดการข้อมูลชื่อและชุดรายชื่อในโปรแกรมเท่านั้น ยังไม่ได้ส่งคำสั่งควบคุมโปรแกรม Camfrog หรือเรียก API เปลี่ยนชื่อโปรไฟล์ภายนอก
- รองรับภาษาไทยเต็มรูปแบบ (สระ วรรณยุกต์ ไม่เพี้ยน) ด้วยฟอนต์ `Tahoma` และระบบ UTF-8
- มีปุ่มสลับ **ชื่อถัดไป (Next ▶)**, **◀ ชื่อก่อนหน้า (Prev)** และช่องระบุชื่อใหม่พร้อมกด **เปลี่ยนทันที (Apply)**
- จัดการชุดรายชื่อ (Preset Pool) ได้ในตัว พร้อมปุ่มรีเซ็ตเป็นชื่อภาษาไทยมาตรฐาน (`ผู้ใช้ camfrog`, `สายคามฟร็อก`, `เบอร์คามฟร็อก`, `ดีเจเสียงใส`, `คนึงนิจ`, `มังกรทอง`)
- รองรับการสั่งงานผ่าน CLI ด้วย `--set-name <ชื่อ>`, `--names <ชื่อ1> <ชื่อ2>` และ `--cycle`

## 12. เบื้องหลัง log ไฟล์

- Room/IM: ปุ่ม GUI **Save & Start** / **Stop** หรือคำสั่ง CLI `start` / `state` / `stop` (แบบซ่อน ไม่มีหน้าต่าง) สถานะ: ปุ่ม **Start**/**Stop** ของตัวเองกับ worker ที่มากับแอป
- แต่ละแอปบันทึก log ข้าง config ตัวเอง (source CLI ใช้ `camfrog_auto.log`) แก้ `config.json` ตอนรันได้ ค่าถูกต้องมีผลใน ~3 วินาที ค่าผิดถูกปฏิเสธและ log ไว้
- Activity Log ของ Status Changer รวมกิจกรรม GUI และ log จาก worker โดยข้อความสถานะที่ส่งสำเร็จจะแสดงเมื่อเปิด `log_message_text` ระบบล้าง activity log และ worker log ทุกวันเวลา 12:00 ตามเวลาท้องถิ่นขณะแอปทำงาน หากปิดแอปไว้จะล้างเมื่อเปิดครั้งถัดไป
- โหมด strict background ยังไม่รองรับและคืน `BACKGROUND_UNSUPPORTED` โหมด `best_effort_background` ถูกปิด เพราะการส่ง combo อาจดึง focus และขัดจังหวะการพิมพ์ worker จะปฏิเสธก่อนเขียนข้อความสถานะ โหมด interactive รอการใช้งานว่าง 2 วินาที (`ZCHAT_USER_IDLE_MS` ใช้ปรับได้; 0 ปิดการรอ) และเลื่อนการส่งเมื่อผู้ใช้ยังทำงานต่อเนื่องเกิน 120 วินาที การเริ่ม worker สร้างโฟลเดอร์ข้อมูลและรอการอนุญาต PID ก่อนเริ่มลูป
- การส่ง status แบบอื่นอาจต้องให้ Camfrog อยู่หน้าสุด Camfrog ต้องเปิดอยู่ (ย่อไว้ได้เฉพาะเมื่อ control ยังเข้าถึงได้ — ตรวจด้วย Discover)

| เสียง error ทุกครั้งที่เปลี่ยนสถานะ | ลอง **combo Enter (test)** ในโหมดทดลองก่อน แล้วตรวจ Activity Log ก่อนเปิดส่งสถานะจริง |
| ควบคุมหน้าต่างผิด/เก่า | แก้ **Window title regex** แล้ว detect ใหม่ |
| Explorer โชว์ไอคอนเก่าหลัง build | cache ไอคอน Windows ย้าย/เปลี่ยนชื่อ exe หรือรีสตาร์ท Explorer |

## 13. ความปลอดภัย

- `dry_run` เปิดเป็นค่าเริ่มต้น คำตอบถูกจำกัดความถี่ (คูลดาวน์รายคน ช่องว่างรวม เพดานรายชั่วโมง)
- บรรทัดที่ไม่ใช่รูป `ชื่อ: ข้อความ` ถูกข้าม คำตอบที่ขึ้นต้นด้วย `/` ถูกบล็อก ไม่มีการเตะอัตโนมัติ
- ห้าม commit รหัสผ่าน cookie token หรือข้อมูลส่วนตัว ไฟล์ cookie อยู่นอก repo เสมอ
- ตรวจเงื่อนไข Camfrog และกฎห้องก่อนเปิดระบบอัตโนมัติ แจ้งช่องโหว่แบบส่วนตัวตาม `SECURITY.md`

## 14. ZChat Control Server

Control server เป็นเครื่องมือผู้ดูแลแยกต่างหากสำหรับใช้งานในเครื่อง ไม่ใช่ Camfrog client ฐานข้อมูล PostgreSQL ทำงานใน Docker volume บนเครื่องนี้ และ dashboard/API ผูกกับ loopback Windows agent ส่งเฉพาะ snapshot ที่ตัดข้อมูลอ่อนไหวแล้ว และส่งต่อคำสั่งผ่าน official client ตามที่รองรับ ตัว server ไม่รับรหัสผ่าน Camfrog, browser cookie, CSRF, CAPTCHA response หรือข้อมูลชำระเงิน การดึง profile แบบ authenticated และ Cloud Bot transport ยังไม่เปิดใช้ อ่านวิธีตั้งค่าและข้อจำกัดปัจจุบันใน [`control-server/README.md`](../control-server/README.md) รุ่น MVP นี้ยังไม่พร้อมใช้งาน production
